Comparative Framework
The five disciplines are complementary control layers. Prompt and Context Engineering shape the model-facing instruction and information; Harness Engineering shapes the executable runtime and control environment; Loop Engineering shapes repeated single-process behavior; and Graph Engineering shapes multi-process topology and information flow. In practice, the harness often implements the loop and graph machinery, so these are distinct design responsibilities rather than mutually exclusive software layers.
Dimension	Prompt	Context	Harness	Loop	Graph
Primary object	Instruction contract and priority	Runtime information, memory, and state	Agent runtime, controls, tools, permissions, and execution environment	One agent’s feedback and execution cycle	Execution and information topology across processes
What it controls	What the model is asked to do and which instructions take precedence	What the model can see, retrieve, retain, and use	What the agent can access and execute, how state persists, and which controls are mechanically enforced	How work acts, checks, retries, recovers, and stops	How nodes specialize, connect, exchange state, route, join, and recover
Typical scope	One response, subtask, or reusable agent instruction	One model turn or evolving agent state	One agent runtime or reusable control plane surrounding one or more model calls	One goal-directed agentic process	A coordinated system of agents/processes
Primary design question	What is the task, priority, boundary, and definition of done?	What information deserves model attention now, and what should persist?	What capabilities, permissions, state, safeguards, and feedback must surround the model for reliable action?	How should the agent continue safely until success or escalation?	Who owns each stage, what may cross each boundary, and how should branches coordinate?
Architecture test: If the model misunderstands the task or priorities, inspect the prompt. If it lacks the right facts, state, memory, or permissions in its working information, inspect the context. If the model has the right intent and information but cannot safely execute tools, preserve state, enforce permissions, recover, or expose useful traces, inspect the harness. If one agent can do the work but needs repeated action, verification, recovery, or human checkpoints, inspect the loop. If the work requires specialized roles, explicit handoffs, branching, parallelism, joins, information boundaries, or failure isolation across multiple processes, inspect the graph.
